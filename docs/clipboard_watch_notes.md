# B3 剪贴板监听入队 · 说明与人工确认清单（t35 / 1.4.1）

## 功能

`general.clipboard_watch`（默认 **True**，设置页「外观与日志」组内开关，即时生效）：

- 监听系统剪贴板 `QClipboard.dataChanged`；
- 只在文本能被 `SteamAPI.resolve_any_url` 解析为工坊物品 id 时动作（filedetails
  链接 / browse 链接 / 纯数字 id），其余内容**立即丢弃**；
- 去重：解析出的 item id 若已在下载队列（queued/active/done，经
  `DownloadManager.snapshot()`）则跳过；
- 入队走既有 `DownloadManager.enqueue()`，不新增队列概念；
- 成功时只在**状态栏**非模态提示（5 秒），失败一律静默——不弹任何模态框。

## 防御性设计（硬约束）

1. 剪贴板**原文不记录、不缓存、不写日志**；只流转解析出的 `(appid, item_id)`。
2. `resolve_any_url` 是纯本地正则，**不发起任何网络请求**；非工坊文本零成本跳过。
3. 开关关闭时 `dataChanged` 被 disconnect（`_clip_connected` 标志位防重连），
   处理器内仍二次判配置，即使信号在解绑竞态下到达也不会入队。
4. `get_file_details` 失败（网络断、限流、物品不存在）→ 静默跳过，不崩溃。

## AppID 回退顺序

链接携带的 appid → `get_file_details` 返回的 `appid`/`creator_app_id`
→ 当前工坊页正在浏览的游戏。三者皆空时仍会以空 appid 入队（与既有「导入 URL」
行为一致，由下载流程兜底）。

## 自动化测试覆盖（tests/test_b3_clipboard.py，34 项全 PASS）

默认开启与连接、链接解析入队、状态栏提示、重复触发去重、非工坊文本静默跳过、
无剪贴板文本缓存属性、详情请求失败静默不崩、空/纯空白不发请求、
开关关闭解绑+处理器 no-op、重新开启即时重连、`_is_new_item` 三组判重、
设置页开关读/写/即时生效、`resolve_any_url` 本地语义、
B5 批量粘贴 token 解析与去重、搜索冷却自动重发待选词（含改词作废）。

## ⚠ 需人工在真机确认（offscreen 平台不可验证）

| # | 场景 | 为什么自动化测不了 | 期望表现 |
|---|------|--------------------|----------|
| 1 | 浏览器/其他程序复制工坊链接 | offscreen 平台 `QClipboard` 不产生 `dataChanged` 事件 | 状态栏出现「已从剪贴板加入下载队列：…」，下载页出现该物品 |
| 2 | 窗口最小化到**托盘**时复制链接 | 同上；且托盘在 offscreen 下不可用（`_build_tray` 直接跳过） | 托盘态照常入队，恢复窗口后下载页可见 |
| 3 | 复制**非工坊**内容（普通文本/网址） | 同上 | 完全无反应，无弹窗、无日志记录原文 |
| 4 | 复制**合集**链接 | 同上；合集展开走 `_import_tokens` 的人工路径 | B3 只入单个物品；合集展开请用「批量粘贴导入」 |
| 5 | 设置页关闭开关后复制链接 | 同上 | 无任何反应；重新开启后无需重启即恢复 |
