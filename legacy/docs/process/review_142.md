## 三、2.0 方向确认（四开放问题逐条答复）

| # | 开放问题 | 团队答复 |
|---|---|---|
| 1 | 路线④ PySide6 深度重构为默认？ | **采纳**。加权矩阵 4.13 四路线第一；敏感度检查（美观权重 0.35）WPF 4.05 vs PySide6 4.03 打平；本会话三起硬崩溃全部落在 Qt 互操作层而非语言层，而 core 域七迭代零回归——"解耦即稳定"经验直接支持先解耦路线。 |
| 2 | QML 混合架构（美观上限 3.5→4.5+）做不做？ | **2.0 阶段暂不做**。先走令牌化（t4/t7 已验证明度阶梯+描边+动画插值可接近 PCL2）；阶段 2 完成后按实测美观度再议 QML 期权。 |
| 3 | 功能 vs 重构资源排序？ | **阶段 0+1 契约解耦优先**。Valve 2026-01-08 工坊版本控制（mod 分支/历史版本）是差异化窗口——若窗口期内可并行一条功能支线（用户需求调研已定位），否则功能排序延后到阶段 2 之后。 |
| 4 | 自动更新是否列入？ | **入 1.5/2.0 议题池，不阻塞交付**。现有 Inno 链可用；Squirrel.Windows/自建差分为候选路线，由 1.5 讨论组再评。 |

**2.0 默认路线确认：阶段 0 契约测试固化 → 阶段 1 core 解耦（事件总线+显式注入+PENDING 显式化）→ 阶段 2 令牌化 GUI → 阶段 3 WPF 期权（按需）。Tauri/Qt C++ 当前团队结构下不推荐。** 终裁权在用户（见 docs/architecture/rewrite_2.0_master_report.md）。
