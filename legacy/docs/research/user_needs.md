## ① 痛点清单（按出现频率排序）

### P1. 下载失败/不稳定：最高频，跨所有来源
- 来源：Streamline #37/#24/#23/#18/#14（5+ 条，「Download fails all the time」AppID 2980270 三 provider 全失败仍 open）；NWD ≈9 条服务端/网络错误；中文社区「订阅后 0b 不下载」「进度卡 0%、-118/324」。
- 场景：普通用户点下载即失败，或游戏大更新后集中失败；国内用户常态性撞网络问题。
- 现有方案缺陷：Streamline 多 provider 仍失败且 issue 无人 close；NWD 依赖自建后端 API——单点故障一旦宕机全网不可用；中文用户只能换下载区/清缓存/重新订阅这种「玄学三连」。
- SWDM 机会点：多 provider 链式回退 + 熔断（**已有**）是直接打击点；增量机会是**失败诊断透明化**——把失败原因（429/403/需要游戏所有权/CDN 过期）翻译成中文可操作提示，而非统一显示"失败"。
- 关联：provider 链（1.4.0）、熔断器、429 请求头研究（已落盘 research/steam_429_403_research.md）。

### P2. "下载成功"是假的：信任杀手，用户最愤怒
- 来源：NWD #7/#8（两条同主题：「Program falsely claims mod download was successful」，用户明确说"下载不可能成功时程序却宣称成功，这会让人错误信任它"）；Streamline #34（下载成功但文件哪儿都不存在）；NWD #14 文件损坏。
- 场景：受限游戏/匿名不可下的物品，程序报成功但目录为空。
- 现有方案缺陷：SteamCMD 静默成功语义（#12339 连失败都不退出），多数工具照单全收。
- SWDM 机会点：**0 字节判定失败并清理残留（已有）**是正确基线；增量机会是**账实核验报告**（库记录 vs 磁盘实际 vs acf 三差集，1.4.2 候选 S2）——把"到底下没下成功"变成可核查事实。
- 关联：0 字节失败判定、SQLite 库；sefrawe 账实核验方案已精读（docs/research/sefrawe_backup_verify.md）。

### P3. mod 更新检查与版本管理：功能诉求最集中
- 来源：Streamline #13（open feature request：「_UPDATE existing downloaded workshop items & Workshop library_」）；NWD #29（只能下到旧版本）；RimSort 文档（acf 更新检查、精细控制更新时机为其核心卖点）；Valve 2026-01-08 版本控制。
- 场景：mod 作者更新后，用户要手动逐个比对/重下；游戏大版本更新后 mod 集体失效。
- 现有方案缺陷：Steam 客户端自动更新不可控、不看兼容性；市面工具的"更新"只比 timeupdated。
- SWDM 机会点：**库更新检查（1.4.1 t37 已完成）**已领先；增量机会是**适配 Valve 新版本控制语义——"最新"不等于"兼容"**，在更新检查结果里区分"有新版本"与"有不兼容当前游戏版本的新版本"。这是官方动态直接给出的差异化窗口，且与 P3 场景天然咬合。
- 关联：库更新检查、详情缓存、元数据补全。

### P4. mod 库管理（列表/分类/批量）：与 P3 并列高频
- 来源：Streamline #13 + #31（不显示已安装 mod 列表）；sefrawe 整个产品即为此生；RimPy/RimSort 生态；3DM 整合包文化（管理粗糙：度盘分享+手工解压）。
- 场景：几十上百 mod 后失控：不知装了什么、哪个启用、哪个冲突。
- 现有方案缺陷：Steam 客户端按游戏分散、无跨游戏视图；RimSort 仅限 RimWorld。
- SWDM 机会点：**SQLite 多维检索 + 批量启用/禁用/分类（已有）**直接覆盖；增量机会是**mod 包导入导出（已有）承接整合包分享场景**——做"整合包作者"的导出与"玩家"的导入闭环。
- 关联：mod 库、mod 包导入导出、导出当前筛选结果。

### P5. 国内网络访问（锁区/白屏/加速）：中文用户第一痛点
- 来源：B站锁区视频（39668 播放/2730 收藏——高热度）；贴吧（钢铁雄心4 吧、steam 吧）；搜狐/迅游/CSDN 专栏。
- 场景：打开工坊白屏、地区限制提示、订阅后 0b。
- 现有方案缺陷：加速器（付费、常驻）；换下载区（碰运气）；网页解析站（steamworkshop.download 已废弃）。
- SWDM 机会点：**匿名 + 多通道 + 请求头反限流（已有）**已天然绕过部分客户端层问题；增量机会是**错误码本地化（-118/324/429 的中文解释与下一步建议）**——把自救四步内置成诊断提示，体感壁垒极低。
- 关联：多 provider 链、Accept-Language/X-Requested-With 头修复（1.3.0 已落盘）。

### P6. 可靠工具的替代真空：用户在找"不会消失的下载器"
- 来源：steamworkshop.download 废弃、SWTools 停更、NWD 停滞（#35 两个月无人理 = 死亡证据）、WorkshopDL 停滞 3 年；Husko/cappig 已归档（1.4.2 竞品调研结论）。
- 场景：用户每次工具失效就要重新找替代品，信任成本极高。
- 现有方案缺陷：单点依赖（自建后端、单一渠道）一旦失效全功能瘫痪。
- SWDM 机会点：**架构性机会**——无自建后端（NWD 教训）、provider 链多路回退、活跃维护。应在 README/手册显式承诺并诚实披露限制（RFC：1.4.2 候选 S5）。
- 关联：无后端纯客户端架构、Inno Setup 安装包。

### P7. 大文件与合集/批量下载
- 来源：NWD #28（150MB+ 壁纸引擎文件失败）；Streamline 整库抓取（上限 50,010）+ 合集下载诉求；SteamCMD 合集下载本身坏的（#11662 open）。
- 场景：壁纸引擎/3A 模组整备、服主整库同步、合集一键拉取。
- 现有方案缺陷：单线程串行下大集合慢；steamcmd 合集路径官方未修。
- SWDM 机会点：**断点续传 + 自动重试（已有）**；**集合批量下载已排 1.4.2**——务必做（需求确证），但范围限定在"合集解析入队"，不碰并行（见路线图 R6）。批量粘贴/剪贴板（1.4.1 已完成）先覆盖了 URL 维度。
- 关联：断点续传、速度采样滚动窗口、批量粘贴、剪贴板监听。

### P8. 免账号/免客户端匿名下载
- 来源：CSDN（Epic 用户、无客户端用户）；B站视频标题即诉求；WorkshopDL 官网定位（"without using the Steam client"）；SWDM README 徽章「下载-免账号匿名」。
- 场景：Epic/盗版/离线机用户想用工坊内容；不想为下个 mod 登录主账号。
- 现有方案缺陷：匿名受限游戏（DayZ 等）不可下是 Valve 设计，工具无法绕过，但多数工具不诚实披露。
- SWDM 机会点：**已有核心卖点**；增量机会是 README 已知限制节诚实披露受限 App 清单（已有，S5 强化）。
- 关联：login anonymous、私人账号 provider 回退（受限 App 场景）。

### P9. 杀毒误报
- 来源：Streamline #19「Trojan spotted」、NWD #33（用户以为中木马、文件夹被隔离）；sefrawe FAQ 专设条目。
- 场景：PyInstaller/steamcmd 打包物被 Windows Defender 误杀，用户恐慌。
- 现有方案缺陷：解释成本全压在 issue 区。
- SWDM 机会点：低成本信任建设——FAQ + 安装器数字签名说明 + 明确的杀软白名单指引（1.4.2 S5 README 范式吸收，已有 Inno Setup 安装包可承载）。
- 关联：Inno Setup 安装包、README/手册文档基建。

### P10. 游戏支持覆盖
- 来源：NWD #34（Cossacks 3 support??）。
- 场景：用户玩的游戏不在工具列表里。
- SWDM 机会点：**内置 59 游戏 + 自定义 AppID（已有）**已解决——可在宣传中显式对比。
- 关联：games.py 游戏选择器。

### P11. mod 冲突/依赖/排序焦虑
- 来源：RimPy/RimSort 生态卖点；极客如何「百 Mod 优化」（冲突、加载顺序、缺依赖是三大焦虑）；TrueSight 淘金指南。
- 场景：装百 mod 后游戏卡加载/崩溃，不知哪个冲突。
- 现有方案缺陷：现有管理器按单游戏做，且多为排序专精。
- SWDM 机会点：**依赖自动下载 + 冲突检测（SWDM 独有，竞品矩阵中唯一）**——强化呈现（库页冲突徽章、依赖树可视化），这是相对所有竞品的最强差异牌。
- 关联：依赖 BFS 自动下载、冲突检测、详情弹窗依赖树。

## ② 对 SWDM 路线图的建议

三原则：**精简**（不新增认知负担/复杂度）、**以用户体感为中心**（体感收益要可感知）、**保证基本功能正常运行**（不破坏下载/库/浏览主链路）。

### 建议「做」（按优先级）

**R1. 账实核验 + 失败可信性强化（P2，1.4.2 C 类首个候选）** ★强烈
- 做什么：库记录 vs 磁盘实际 vs acf 三差集报告；下载终态"成功"必须由文件存在性背书。
- 三原则：精简✓（一个核验动作）；体感✓✓✓（直击信任杀手 P2，NWD 双 issue 的愤怒可证）；基本✓（只读核验，不阻断主流程）。
- 依据：NWD #7/#8 + Streamline #34；sefrawe 方案已精读可参考（docs/research/sefrawe_backup_verify.md）。

**R2. 集合批量下载（P7，1.4.2 已排期）** ★强烈
- 做什么：合集页解析 → 依赖 BFS 一并入队（复用现有依赖下载）。
- 三原则：精简✓（一个入口）；体感✓✓（合集/服主场景刚需，SteamCMD 官方合集路径坏的正好是空档）；基本✓（入队复用串行调度）。不做并行（见 R6）。

**R3. 更新检查适配 Valve 版本控制语义（P3，1.4.2/1.5）** ★推荐
- 做什么：更新检查结果区分"有新版本"/"有不兼容当前游戏的新版本"（metadata 若暴露兼容版本字段则标注；未暴露则在 UI 预留语义位）。
- 三原则：精简✓（检查逻辑增量，非新功能）；体感✓✓（游戏更新后 mod 集体失效是最高焦虑场景之一，官方 2026-01 已给 API）；基本✓。
- 依据：Valve 2026-01-08 公告 + Streamline #13 + RimSort 卖点。注意风险：字段尚未全量铺开，先做 UI 语义、不强依赖新字段。

**R4. 失败诊断透明化/错误码本地化（P1+P5，1.4.2 低成本快赢）** ★推荐
- 做什么：429/403/-118/324/"需要游戏所有权"的中文解释 + 下一步建议（换通道/登录/稍后重试），替代统一"失败"文案。
- 三原则：精简✓（文案+错误分类）；体感✓✓✓（国内用户第一痛点 P5 的低门槛解）；基本✓（不动调度逻辑）。429 与请求头研究已落盘可复用。

**R5. 信任层文档建设（P6+P9，随 1.4.2 README 改造）** ★推荐
- 做什么：README 加"当前限制"节（诚实披露受限 App）、杀软误报 FAQ、无后端架构承诺。
- 三原则：精简✓（纯文档）；体感✓✓（P6 真空期用户最看重"会不会消失"）；基本✓。依据：Apricityx/sefrawe/Streamline 共同范式（竞品调研 S5）。

**R6（保留位）. mod 包导入导出强化整合包分享场景（P4）** 可选
- 现有能力已覆盖基础闭环；若 1.4.2 有余力，做"导出含启用状态/加载顺序的分享清单"。三原则均✓，中低优先级。

### 建议「不做」

**N1. 并行 SteamCMD 下载**（来源：Workshop-Controller）
- 否决理由：违背"精简"（worker 池+staging 隔离大幅升复杂度）；违背"基本功能正常运行"（新增失败模式，Workshop-Controller 自己 2026-09-08 还在修 worker 清理与 0 字节的坑）。SWDM 串行化是有意设计。与 1.4.2 竞品调研 S8 一致。长期观察。

**N2. 自建后端 API 服务器**（NWD 反面教训）
- 否决理由：NWD ≈9 个 issue 全因后端单点故障；SWDM 无后端架构是 P6 真空期的核心优势，不可倒退。

**N3. DepotDownloader/.NET 引擎入 provider 链**
- 否决理由：引入 .NET 运行时依赖，灰区风险，收益/工作量比差（竞品调研 S9 一致）。

**N4. 网页解析站式路线（steamworkshop.download 模式）**
- 否决理由：已废弃验证该模式生命周期短、法律风险高；SWDM 客户端 + 官方接口路线符合"基本功能长期正常运行"。

**N5. Linux/移动端跨平台（本期）**
- 否决理由：Streamline Linux 构建 issues 多为环境边际问题（#35 打包 steamcmd 二进制坏、#32 COSMIC 拖不动窗口）；SWDM 精力应聚 Windows 主链路体验。记录为长期方向（B站"手机下工坊"热度存在，非当前阶段投入项）。
