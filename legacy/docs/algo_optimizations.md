# 资源开销盘点与优化清单（SWDM 1.3.6 基线）

> 盘点方式：源码审计 + 压力测试（tests/test_stress.py，60 张卡片填充 115ms，
> 约 1.9ms/卡，为当前主要渲染成本）。以下每条含现状（文件+行号）、问题、
> 改法、预期收益。按预期收益排序。

## 优化清单

### 1. 图片加载回调 O(N) 全表扫描（高收益）
- **现状**：`swdm/gui/workshop_tab.py:867` `_on_image_loaded` 对每张到达的图片
  遍历全部卡片 `card.item.preview_url == url`。30 张卡片 + 30 张图片 = 900 次比较。
- **问题**：每张图片到达都做一次全表扫描；图片并发到达时重复扫描叠加。
- **改法**：`_populate` 时建立 `preview_url -> card` 字典，回调直接 O(1) 查找。
  注意同一 URL 可能被多张卡引用（相同预览图），值用 `list[card]`。
- **预期收益**：图片回调从 O(N²) 降到 O(1)；翻页越快收益越明显。

### 2. 图片缓存整体 clear 而非 LRU 淘汰（中收益）
- **现状**：`swdm/gui/workers.py:129-130` 缓存超 300 张时 `_image_cache.clear()`
  一次性清空。
- **问题**：清空后当前可见卡片全部重新下载，造成网络请求突刺； QPixmap
  反复构造销毁。
- **改法**：改用 `OrderedDict` + `move_to_end`，超限时弹出最旧条目（约 50 张），
  保留当前页常用图。
- **预期收益**：翻页回看时图片命中缓存；网络请求平滑。

### 3. 图片在主线程同步下载回退（中收益，卡顿风险）
- **现状**：`swdm/gui/workers.py:153-162` 当 `fetch_image` 回退返回原始 URL 时，
  在主线程 `_session.get(local_path, timeout=20)` 同步下载。
- **问题**：主线程同步网络请求，超时 20s 期间界面完全无响应（用户反馈的
  "无响应"直接来源之一）。
- **改法**：把该回退也丢进 QThreadPool，或直接返回失败让占位图保留，
  不在主线程做任何网络 IO。
- **预期收益**：消除主线程网络阻塞，无响应场景根除。

### 4. 详情页缓存无上限（低-中收益，长期内存）
- **现状**：`swdm/gui/detail_dialog.py:356` `_page_cache` 是进程级字典，
  只设 TTL 300s，无容量上限。
- **问题**：长时间运行 + 浏览大量 mod，字典无限增长（每个详情页 HTML 约
  100-300KB，1000 个 = 100-300MB 常驻）。
- **改法**：加上限（如 100 条），超限删最旧；或改为 `functools.lru_cache`。
- **预期收益**：内存占用有界，长会话不膨胀。

### 5. 卡片创建未批量延迟渲染（低收益，大列表场景）
- **现状**：`swdm/gui/workshop_tab.py:_populate` 一次性创建全部卡片 widget。
- **问题**：60 卡 115ms 可接受，但若单页物品增至 100+ 或缩放窗口时
  `_apply_elide` 全量重算会有明显停顿。
- **改法**：滚动区可视区域外卡片延迟创建（`QScrollBar` value 变化时按需构建）。
- **预期收益**：首屏速度翻倍；仅大列表场景有收益，当前 30 卡页规模非必需。

### 6. enrich 批量未复用会话连接（低收益）
- **现状**：`swdm/core/steam_api.py:enrich` 每 50 个 ID 一批 `get_file_details`，
  复用 session（已较好）。
- **问题**：无显著问题。可记录的是首批请求串行，延迟随页数线性增长。
- **改法**：可选——把元数据补全移到卡片渲染之后（先出列表，再异步刷新
  订阅数/大小），用户感知更快。
- **预期收益**：首屏感知速度提升；抓取总时长不变。

## 压力测试基线（tests/test_stress.py）
| 场景 | 耗时 | 结论 |
|---|---|---|
| 填充 30 张卡片 | 56ms | 正常 |
| 再次填充 30 张（翻页） | 49ms | 正常 |
| 填充 60 张卡片 | 115ms | ~1.9ms/卡，渲染成本 |
| 标签栏填充 77 个 | 18ms | 正常 |
| 打开详情弹窗 | 19ms | 正常（本地数据） |
| 下载页添加 20 行 | 1ms | 正常 |
| 切换 5 个 Tab | 4ms | 正常 |

> 无 >100ms 的业务逻辑卡顿点；唯一慢点是 60 卡渲染本身。优化项 1/3 优先。
